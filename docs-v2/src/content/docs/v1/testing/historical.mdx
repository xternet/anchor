---
title: Historical tests
description: Run RPC-based tests against a chosen historical Solana state.
---

Historical tests use Surfpool's public RPC, backed by SVM Replay's historical
accounts and runtime. Each test chooses its own transaction or slot boundary;
Anchor does not start a shared historical validator or replace its clients.

## Requirements

- A Surfpool build supporting `start --after`, and an installed compatible SVM
  Replay runtime bundle. Ordinary Anchor tests do not require SVM Replay.
- Historical account access configured through a supported provider. Alchemy is
  the currently qualified adapter; an ordinary mainnet RPC key is not enough
  unless it also enables the required archive endpoints.
- A supported host. Historical Surfpool binaries are currently qualified on
  Linux x64; macOS arm64 requires release qualification. Windows is refused:
  SVM Replay runtime support and fork-process cleanup are not qualified there.

## Create a workspace

```sh
anchor init demo --test-template mocha --historical
cd demo
export API_ALCHEMY="your-account-archive-key"
anchor build --arch v0
anchor test --skip-build --skip-deploy
```

Mocha and Jest support TypeScript or JavaScript. RPC-based Rust tests also support
`--historical`; LiteSVM and Mollusk run in-process and explicitly refuse it.
Both supported program template versions, including single-file variants, use
the same per-test fork model.

The scaffold adds provider settings to `Anchor.toml`:

```toml
[historical]
provider = "alchemy"

[historical.providers.alchemy]
adapter = "alchemy"
key_env = "API_ALCHEMY"
```

The provider name selects an adapter configuration; it is not a key or RPC URL.
`key_env` names an environment variable. Do not commit a literal API key.
Provider-specific endpoints are handled by the adapter, not by Anchor tests.

## Choose the state in test code

The generated test calls `HistoricalFork.start({ after: "413023260" })`. A numeric
boundary means after that slot; a transaction signature means immediately after
that transaction. The helper accepts either without a `slot:` or `tx:` prefix.

The generated test then funds its local wallet, installs the compiled program,
declares the account it will create, and advances one slot before calling the
program. `installProgram` is Surfpool's fast ELF setup, not a loader deployment.
Use an SBPF format supported by the boundary runtime (`v0` for this example).

| Helper | Purpose |
|---|---|
| `provider()` | Explicit Anchor provider for this fork; no global rebinding |
| `setAccount(address, values)` | Fork-local account setup |
| `installProgram(programId, soPath)` | Fork-local program setup |
| `advance(slots)` | Explicit local clock advance; frozen by default |
| `rpc(method, params)` | Ordinary RPC and supported Surfpool controls |
| `close()` | Stop this fork; remove listeners before closing |

Use `try/finally` or test teardown to close each fork. Anchor also reaps recorded
forks left by a crashed test process. No operation is sent to mainnet.

## Fixtures and limits

The ordinary fixture compiler supplies `[test.validator]` `fund_accounts`, `mints`
and `token_accounts` to every fork. Known clone addresses are loaded lazily from
the chosen boundary, not copied from current mainnet state.

Historical suites refuse these configurations before installing fixtures:

- `[[test.validator.account]]` and `[[test.validator.account_dir]]`: use
  `setAccount` in the test instead.
- `[[test.genesis]]`: use `installProgram` in the test instead.
- `[test.validator] url`: select the archive through `[historical]` instead.

Missing provider data returns an explicit error; it never falls back to the tip.
Some historical queries require indexes the provider does not supply. Durable
nonce execution additionally needs the historical RecentBlockhashes sysvar,
which the qualified Alchemy archive does not currently provide.

Only `anchor test` opts into the suite plan. Other commands, including
`anchor localnet`, do not automatically use `[historical]`; give their clients an
explicit fork endpoint when applicable. Existing tests without `[historical]`
keep the ordinary validator path.

An incompatible Surfpool is refused with `SURFPOOL_INCOMPATIBLE`; inspect the
selected `surfpool` on PATH and install a historical-capable build. The local
launch-capability check does not download tools or contact a provider.
